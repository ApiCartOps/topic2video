## 1. Project conventions
- Frame number **N = useCurrentFrame() + F0** (F0 = the shot's ShotDef.from; inclusive). Frame numbers in the storyboard and timeline are all N.
- Build groups G1–Gn. Each chapter has two groups of 5–7 shots each. Group count follows length; the sample tier uses 8. The overlay (`src/overlay/`: opening, chapter cards, top HUD, flow track, closing) is maintained by the main session, and build groups do not draw it. Each shot is one component file, `src/shots/Gn/SCxx.tsx`. `src/shots/Gn/index.ts` exports `SHOTS_Gn: ShotDef[]` (`{id, from, to, Comp, layer?}`, where array order is the stacking order) and `BG_Gn: BgSpec[]` (background overrides, see below). **Only edit `src/shots/Gn/**`.** Do not change Main, Root, common or other groups. If a shared-layer change is needed, record it in `src/shots/Gn/BUILD_NOTES.md` and raise it in your final reply.
- Project graphics library `src/ui.tsx` (import from `'../../ui'`): palette PURPLE / PURPLE_LIGHT / PURPLE_TECH / ORANGE / CORAL / RED_DEEP / GREEN / GREY / GREY_LINE / WHITE, GLOW_* / BLOOM / TEXT_GLOW. Components `CText / TechText / MonoText / Box / Pill / TagBlock / Svg / LineArrow / ArrowH / Check / Cross / DocIcon / DBIcon / ChunkCard / LLMIcon / TopCapsule / Counter`. Motion helpers `fadeIn / fadeOut / slideUp / scaleIn / exitAccel / exitFade / stagger / abs`. **Use these first** to keep the visual style consistent. If something is missing, add it inside your own group directory. Do not change ui.tsx. Anything that should go into ui.tsx goes in BUILD_NOTES.
- Light, highlight-moment, depth and camera effects in `src/fx.tsx` (import from `'../../fx'`): `LightBar / LightSweep / StageLine / GhostText / ghostOpacity / HaloRing / HeroGlow / BigNumber / countTo / Sparkle / GradBall / TiltPlane / CameraRig / camAt / SET_PIECE / setPiece`.
- Shared layer from `'../../common'`: `GlitchIn` (12-frame glitch entry), `kf / stepKf / slideIn / powOutRemain / expOut / powIn / easeInOutPow / cubicBezier / BEZ_SCALE_IN / emphasisPulse / rnd`, `StarField / Fog`, `FONT_HEAVY / FONT_TECH / FONT_WIDE / FONT_ORB / FONT_MONO / FONT_SERIF`, `DirBlur`, `SubtitleLine / strokeShadow` (reuse for outlined text styles; this does not draw subtitles), `TOTAL_FRAMES / CHAPTER_STARTS / SENTENCES`, `FootageTrack` (optional live footage). Main loads the fonts globally through `Fonts` (Noto Sans SC 100–900, Exo 2 Italic, Audiowide, Orbitron). **Do not** load fonts again with delayRender inside components.
- Always-on layers are rendered by Main, in this stacking order: black base, then backdrop (`config.bg`: fog `Fog` (y415→720, #000→#212121) plus star field `StarField`, or dot wave `DotFieldBg`), then your shots, then the progress bar (y687–720, semi-transparent), then `layer:'aboveBar'` shots, then subtitles. **Shot components must not draw an opaque black background** (it covers the backdrop). If you really need pure black or no stars (for example the first frame of the opening, or a deliberate blackout), use `BG_Gn: [{from, to, fog:false, stars:'none'}]`.
- Randomness only through `rnd(...seeds)` (deterministic). `Math.random` is banned. All animation is a pure function of N, so do not use useState or useEffect for animation.

## 2. Safe area
- The top HUD capsule (533,28,216,51) and the flow track for chapters 2 and 3 (y 112–160) are drawn by G0. **Build groups must not draw them**, and must not put content above y100 (chapters 1 and 4) or y175 (chapters 2 and 3).
- Content area: **y 110–620** for chapters 1 and 4, **y 175–620** for chapters 2 and 3 (x 60–1220). The subtitle band **y637–690 must not hold anything that needs reading.** The progress bar y687–720 may only be crossed by full-width background or large shapes (they brighten where they cross the bar, which is the original style and is allowed).
- Minimum type size 22px. Body labels 26–34px. Headings 44–72px. English technical terms use FONT_TECH (italic, `scaleX 0.8–0.9`).
- **English video (`lang: 'en'` in config.ts):** do **not** squeeze Latin letters with scaleX (use the `SQUEEZE` constant: Chinese .85, English 1). Leave the `dy` on centered text at its default (`TEXT_DY` gives −2 for Chinese and 0 for English automatically); do not hand-write −2. English runs much wider than the same number of Chinese characters, so estimate widths with `textW(s, size, EM_*)` (`common/textfit.ts`) rather than by eye. See style-guide.md §3.1.

## 3. Motion and rhythm (details in motion-vocabulary.md and composition-and-light.md)
- **Protagonist and size:** each shot has one protagonist, at least 170px tall or large type ≥96px, entering on beat 1 or 2. Three size tiers: protagonist ≥170, supporting 60–110, labels 22–30. The largest object in the content area staying under 110px for more than 45 frames is a defect. Small subjects such as timelines, formulas and tables must have a protagonist (a big number, or the current item enlarged).
- **Light follows the protagonist:** the protagonist always carries `GLOW_PURPLE`, `HeroGlow`, `HaloRing`, or purple hard shadow on large type. Capsules, flow tracks, labels and tables are not lit by default. At most one `GLOW_PURPLE_S` on the current emphasis. Light goes off before exit.
- **Highlight moments:** shots on the highlight list in the storyboard's global constraints follow composition-and-light.md §3 (`LightSweep` → `StageLine` → `GhostText` → white flash with `GlitchIn` → pulse → subtitle → word-by-word labels), at least 90 frames. Do not handle them with "capsule + icon + one line of text".
- **The backdrop is only the backdrop** (stars or dot wave). Do not scatter small icons for atmosphere. For "many", use a grid of ≥6px squares that light up on the beat.
- **Depth:** for space, hierarchy and indexes, stack `TiltPlane` layers. For filtering, use `Trap`. Rotation is only for gears, dials and wheels.
- **Continuous motion** (composition-and-light.md §7): each subtitle block's verb has an action that continues until the next beat. No element stays completely still for more than 30 frames after entering. A shot without another camera move gets a slow 1.0→1.05 push-in (content stays within x 89–1191, y 122–607). Before finishing, run `python3 scripts/motion_check.py <Gn>`: each shot's still share ≤40%, longest still ≤0.7 s (the final-cut measurement is stricter). Record the numbers in BUILD_NOTES.
- **Use the shared helpers:** `softOp / firstOp / exitOp / glowOffK / mix / mixHex / glowPurple(k) / glowPurpleS(k)` (ui.tsx) and `GlowBlob / Vignette` (fx.tsx). Use `firstOp` for first-frame entry (`fadeIn(0)=0` leaves a blank frame). Use `exitOp` before a hard cut. Use `glowOffK` to turn light off before fading a glowing element.
- Three entry styles to choose from: the 12-frame GlitchIn template (titles, capsules, key terms); a bottom-up slide `y = yEnd + Δ·powOutRemain(n,22,2.5)` with Δ≈300 (graphics and cards); or a 21-frame scale-in `s = s0+(1−s0)·BEZ_SCALE_IN(n/21)` (icons). Lists and card arrays stagger by **2 frames**.
- Line and arrow draw-on: an SVG `clipPath` rect or stroke-dasharray. Arrows **grow from the root**, 16–28 frames.
- Emphasis: `emphasisPulse(n, {peak: 1.11})`, grey to purple color change over 11 frames, glow `box-shadow 0 0 24px 8px rgba(102,45,248,.6)`.
- Exit: an ease-in curve `Δ = c·t^2` (t in frames) for a downward or leftward drift, plus a 6.7% per-frame fade (about 15 frames), or a hard cut to the next shot. Adjacent shots **leave no blank frames between them** (the backdrop is always present, so 0–3 frames of overlap are fine).
- Beats: an element enters aligned to the **subtitle block start frame** of its narration line (each ｜ block in timeline.md). A key term appears no later than +3 frames and no earlier than −6 frames from its block start.
- **Camera:** follow the camera-move list in the storyboard. At least 3 per chapter, at most 1 per shot. Use `CameraRig` (fixed push-in 1→1.33 over 33 frames, pull-back 37–42 frames, carry-shift 16 frames, group pan, parallax on 2–3 layers). Do not run GlitchIn or staggered entries during a move. HUD, flow track and subtitles stay still. When a sentence has no new element, use one push-in instead of forcing in an element. Vocabulary and frame counts are in motion-vocabulary.md, camera moves section.

## 4. Performance limits (violations slow the whole render by 10–50×)
- No `feConvolveMatrix`. Use `filter: blur()` or feGaussianBlur with σ≥1 (σ<0.8 does nothing in Chromium). SVG filters need `colorInterpolationFilters="sRGB"`.
- DOM nodes per frame ≤600, SVG filter instances ≤6, OffthreadVideo ≤1. Generate particles and grids with pure functions of N. Do not allocate large arrays every frame.
- Before finishing, run a 30-frame test render and check fps (see §6). Below 3 fps, find the cause.

## 5. Self-checks (required; record in BUILD_NOTES)
- `npx tsc --noEmit` passes (run in the remotion directory).
- Each shot produces **at least 6 stills**: first entry frame +1, mid-entry, entry complete, a middle keyframe, mid-exit, and the last frame. Command: `<project-root>/scripts/still.sh Gn <frame list, comma-separated> <absolute output directory> gN`. **The tag is fixed to this group's gN, and each group keeps one bundle.** After a code change, `rm -rf <project-root>/build_dev_gN` before rebuilding. A bundle is about 40 MB, so do not stack several. **Never** run `npx remotion still src/index.ts …` directly (it creates a temporary bundle in $TMPDIR every time, and once filled the disk). The test render goes to /tmp/explainer_test_gN and is deleted once you've checked it. The still.sh output directory **must be an absolute path** (the script changes into the project root). Output to `<project-root>/stills/Gn/`. **Look at the images with Read** and check: is any text covered by the subtitle band, progress bar or HUD; does anything overflow the canvas; do colors match the palette; are English spellings correct; do numbers match the research; does each element appear within ±6 frames of its subtitle block start. **Protagonist glyph height ≥170px, protagonist lit, no debris in the background.** Highlight-moment shots need at least 10 stills covering the light sweep, white flash and glitch sections. Shots with camera moves need 3 stills of the push-in (first, middle, last).
- For the boundary with each neighboring group: one still of the first frame and one of the last frame of this group's first and last shots, saved as `<project-root>/stills/Gn/boundary_*.png`.

- Final reply covers only: number of shots completed, tsc result, test-render fps, the still directory, and decisions the main session needs to make. **Write to disk as you go**: update index.ts and BUILD_NOTES after every one or two shots, rather than saving everything for the end.

## 8. Glitch allow-list (user decision 2026-09-06: "don't add glitch to every line, only key terms")
- **Each shot gets at most one glitch, and only on that shot's key term** (listed below). Everything else (text, labels, capsules, numbers, icons) enters with `SoftIn` (`ui.tsx`: an 8-frame fade-in plus 10px rise, same signature as GlitchIn, so it can replace it directly), or with fadeIn, slideUp or scaleIn. The main session handles HUD term changes with SoftIn.
- The allow-list is given at the end of `分镜表.md` under "global constraints" (one key term per shot at most; a sample is in skill `examples/rag/AGENT_RAG_BUILD_RULES.md` §8). **Shots not on the list get no glitch at all.**
- Heavy RGB-split or slice glitch is only allowed for the opening, chapter-card titles, protagonist entrances, and the closing large text.
